# QA sweep — 14 September 2026

## Scope and evidence

Production checked: `https://envolio.travel`, release commit `5a9401a9d355c8556e18e2accc7fcb60a29f066a`. Health and alert-capability endpoints returned 200. A bounded real AA100 lookup for September 15 returned 200 with Scheduled status. Production email/SMS capabilities were correctly false. No test messages were sent.

The initial sequential `tests/*.test.mjs` run completed **105 tests: 93 passed, 12 failed**. Six failures were the live-provider regression suite pointed at the local fixture-only host, which deliberately returns 503; those are not verified provider regressions. One browser test began before its expected local server existed. The remaining five failures were obsolete UI assumptions in intelligence, codeshare title, error copy, inbound ordering and strategy markup. Corresponding test expectations were updated to follow the current collapsed-details layout and traveler-facing copy. These updated older suites still need a clean complete rerun; this is **not** an all-green certification.

Passing initial coverage included provider adapters, FAA/EDCT/slot behavior, operational-risk and source-audit checks, parser/date/route handling, traveler presentation, saved cards, home examples, search clarification, security/rate guards and isolated Docker runtime startup. The Docker check copies the runtime dependency set and starts it; it is not a Docker-engine image build.

## Changes

- Guard gate/terminal browser-storage reads and writes against SecurityError.
- Normalize corrupt notification preferences to known boolean options.
- Protect notification construction on mobile browsers that expose permission but reject direct notifications.
- Reject incomplete/out-of-range tail-map coordinates in the presentation layer instead of calling `toFixed` on missing values.
- Add privacy-restricted storage, empty-response and keyboard-modal regression coverage.
- Add feature-gated managed accounts, private saved-flight tables, account preference sync, explicit migration of local saves, and consent-checked email outbox infrastructure; see `ACCOUNTS-NOTIFICATIONS.md`.

No delay-model weights, scoring factors, weather thresholds or aviation calculations were edited.

## Release limits

Do not claim the massive QA sweep is fully green. Physical iPhone/Safari, complete refreshed public-browser traversal, real Supabase two-account isolation, real email-code delivery, notification sending/unsubscribe, provider-plan coverage and the full revised legacy browser suite still require verification. Accounts and background email stay disabled by default. The database migration has not been applied to a live project. The trusted flight-monitor-to-outbox bridge is not deployed. SMS/web-push and self-service account deletion/export are not complete.
